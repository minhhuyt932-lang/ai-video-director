# 第 1 步：从一个想法到完整剧情

用户带着一个想法来，不用很详细。你和用户一起聊，把它完善成完整的故事，等用户确认后再展开成逐镜头故事。**用户确认故事之前不画任何图。**

## 好故事的 5 条标准

1. **符合现实逻辑**：每个转折都按现实追问一遍：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？（除非片子本来就不讲现实逻辑。）
2. **能用一句话说清想表达什么**：说不出来，片子大概率很平淡，要再改。也问问自己剧情哪里设计得最好。
3. **开头就要抓人**：观众几秒就可能划走，最抓眼球的画面放在最前面。
4. **旁人的反应要像真人**：每个包袱或转折都分 3 段写：问题 → 主角怎么解决 → 旁人什么反应。反应要有先后，几个人同一秒举手一看就是模型做的。细节也要真，比如人吃惊时身体会往后缩。
5. **AI 拍得出来**：在写故事阶段就避开 AI 视频的固定弱点（见下）。

## AI 视频的固定弱点（写故事时就避开）

人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一镜内换光、一人连做三个动作、俯拍看不到脸、配角太多。这些画面很难一次到位，抽卡率高。

## 故事结构

- **片段式（首选）**：镜头之间不用接戏，最稳。
- **连贯式**：最容易穿帮，镜头之间的衔接要格外注意。除非用户要求，否则不用。

## 提示词：想法 → 完整剧情

```
我想做的片子：[一句话，或者我的初步剧情]。片长：[秒]。
配歌：[歌名、时长、BPM；不配歌就删掉]。
参考片：[有就写，没有就删掉]。

先帮我把这个想法完善成一个完整的故事。有不清楚的地方就问我，我们一起聊，等我确认了再往下写。
故事结构首选片段式，因为每个镜头之间都不用接戏，最稳。连贯式最容易穿帮，除非我要求，否则不要用。

故事确定以后，展开成逐镜头的故事，要满足下面这些要求：
1. 符合现实逻辑。每个转折都按现实追问一遍：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？
2. 能用一句话说清想表达什么。先把这句话写出来，说不出来就说明故事还要改。
3. 开头就要抓人。最抓眼球的画面放在前面，写清楚第几秒出现什么。
4. 旁人的反应要像真人。每个包袱或者转折都分 3 段写：问题 → 主角怎么解决 → 旁人什么反应。反应要有先后，不能几个人同一秒做同一个动作。细节也要真实，比如人吃惊时身体会往后缩。
5. 要让 AI 拍得出来。避开这些弱点：人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一个镜头里换光、一个人连做三个动作、俯拍看不到脸、配角太多。

如果配歌，转折对副歌，关键动作对重拍。
```

## 剧情审核（新开子 agent）

故事差不多定稿后，**新开一个子 agent 审核，只给它定稿的逐镜头故事，其他文件和结论一概不给**。

为什么：主 agent 已经和用户聊了很久，知道用户想说什么，看故事时会自动脑补。新 agent 像第一次看片的观众，它哪里看不懂，就说明哪里真没讲清楚。

发给审核 agent 的提示词：

```
这是一支短片的逐镜头故事。你是第一次看，只负责挑错，不改文件。
1. 只按镜头顺序读，先写出你看懂的故事。
2. 按顺序追问每个转折：为什么会这样？东西从哪来？够得着吗？现实里真会这样吗？
3. 能用一句话说清想表达什么吗？
4. 开头抓人吗？最抓眼球的画面放在前面了吗？
5. 旁人的反应像真人吗？有没有先后？
6. 哪些镜头 AI 视频模型容易拍错？（人物交叉、手拿小东西、文字、镜子和倒影、左右不对称的特征、一个镜头里换光、一个人连做三个动作、俯拍看不到脸、配角太多）
每条写：镜头、问题、建议改法。没把握的写“可能”。最后写“通过”或“不通过”。
```

把审核意见整理给用户，改完、用户确认，故事才算彻底定稿。
